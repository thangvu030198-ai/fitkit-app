# FIT KIT — Brief chung cho các agent phát triển (đọc kỹ trước khi code)

## Dự án
- App tập luyện + dinh dưỡng + kết nối PT↔học viên, **tiếng Việt**, vanilla JS SPA (không framework, không bundler), đóng gói Capacitor 6 cho iOS/Android, chạy web tại https://thangvu030198-ai.github.io/fitkit-app/
- Mã nguồn (đường dẫn shell): `/sessions/quirky-magical-gauss/mnt/outputs/FitKit/`
- Thứ tự nạp script (index.html): icons.js, firebase-config.js, media-config.js, cloud.js, data.js, templates.js, exdb.js, app.js, meals.js, nutrition.js, freevideos.js, video.js, library.js, coach.js, ptprofile.js, pt.js, **← module của bạn sẽ được nạp SAU pt.js**.
- `pt.js` gọi `appBoot()` ngay khi nạp → khi module của bạn chạy, app đã khởi động. Nếu bạn ghi đè hàm render, hãy gọi lại render màn đang mở nếu cần.

## Biến/hàm toàn cục dùng được
- `state` (lưu bằng `saveState()` vào localStorage key `fitkit_state_v1`): `state.profile` {name, gender "male"/"female", age, height, weight, activity, goal "lose"/"maintain"/"gain", goalKcal, protein, carbs, fat, bmr, tdee}, `state.plans` {id: {name, tagline, days:{T2..CN:{title,intensity,duration,items:[{uid,exerciseId,sets,reps,restSec,stock?,clipId?}]}}}}, `state.activePlanId`, `state.workoutLog` {date:{dayKey,completedExerciseIds,finishedAt}}, `state.foodLog` {date:{breakfast,lunch,dinner,snack:[{name,grams,kcal,protein,carbs,fat,recipe?}]}}, `state.waterLog`, `state.setLog` {exKey:{date,sets:[{kg,reps,rpe}],reps,fails}}, `state.setHist` {exKey:{name,list:[{date,e1rm,top,vol,sets}]}}, `state.finishedDates`.
- Hàm: `$(sel, root)`, `$$(sel, root)`, `toast(msg, icon)`, `openSheet(html)`, `closeSheet()`, `onSheetCloseHook`, `confirmDialog(title, msg, onConfirm, label, icon)`, `goto(screen)` (home, workout, nutrition, coach, profile, plans, library, progress, exlib, sleep, reminders), `escapeHtml`, `todayStr(date)`, `pad2`, `fmt1`, `getActivePlan()`, `todayDayKey()`, `getExerciseMeta(item)`, `recomputeProfile()`, `getDayFoodLog(dateKey)`, `renderWorkoutScreen()`, `renderNutritionScreen()`, `renderHomeScreen()`, `renderProfileScreen()`, `renderProgressScreen()`, `renderCoachScreen()`, `startSession(dayKey)`, `openTemplateBrowser()`, `tplToPlan(t)`, `tplAddToWeek(t)`.
- Dữ liệu: `EXERCISES` (id → {name "Tên Việt (English)", muscle, equipment, sets, reps, restSec, img, guide}), `DAY_KEYS` ["T2".."CN"], `DAY_LABELS`, `MEAL_TYPES`, `GOALS`, `ACTIVITY_LEVELS`, `FOODS` (mỗi 100 g: id,name,kcal,protein,carbs,fat, tuỳ chọn portion/unit), `RECIPES` (meals.js), `PROGRAM_TEMPLATES` (templates.js), `bodyAnalysis(p)`, `buildDayPlan(p, dayIndex, prefs)`, `recipeMacros(r)`, `foodPic(id)`.
- Đám mây: `cloud` (cloud.js) — `cloud.mode` ("demo"/"firebase"), `cloud.user`, `cloud.profile`, `cloud.myClientsAsPT()`, `cloud.getClient(id)`, `cloud.updateClient(id, partial)`, `cloud.listSessions(cid)`, `cloud.saveSession(cid, s)`, `cloud.addNote(...)`. Chế độ demo lưu localStorage.
- Icon: viết `<span class="material-symbols-rounded">tên_icon</span>`; icons.js tự đổi thành SVG. Tên chưa có sẽ hiện chấm tròn → thêm icon mới bằng `Object.assign(FK_LINE, { ten_icon: "M… path SVG 24×24 nét" })` trong module của bạn (nhiều path nối bằng `|`, hình tròn `c:cx,cy,r`, chữ nhật `r:x,y,w,h,rx`).

## Thiết kế
- Phong cách "liquid glass" tối. Màu: Navy `#061A24` (`--navy`), Mint `#5EE6C7` (`--mint`, `--mint-2 #9AF1DD`), Coral `#FF7A45` (`--coral`, CTA chính). Font Inter / Inter Tight (`--font-head`).
- Lớp sẵn có: `.card`, `.card-title`, `.pill` (`.active`, `.hot`), `.chip-row`, `.btn .btn-primary/.btn-outline/.btn-ghost .btn-block .btn-sm`, `.sheet-header`, `.icon-btn`, `.field` (label + input), `.stat-grid/.stat-box(.num,.cap)`, `.small-note`, `.empty-hint`, `.section-title`, `.list-item`.

## QUY TẮC LÀM VIỆC (rất quan trọng — nhiều agent chạy song song)
1. **Chỉ tạo file MỚI** của riêng bạn: `FitKit/<module>.js`, `FitKit/<module>.css` (nếu cần), dữ liệu kèm theo, và `FitKit/docs/INTEGRATION-<module>.md`. **KHÔNG sửa** index.html, app.js, style.css, pt.js, coach.js, nutrition.js, meals.js, templates.js, data.js, cloud.js… (trừ khi task của bạn ghi rõ file được phép sửa).
2. Tích hợp bằng cách **ghi đè hàm toàn cục** (mẫu: `const _old = renderX; renderX = function(){ _old.apply(this, arguments); /* chèn UI */ };`), chèn DOM, hoặc thêm nút vào màn sẵn có. Module phải tự chạy khi được nạp sau pt.js, không phá vỡ app nếu lỗi (bọc try/catch).
3. Dữ liệu mới lưu trong `state.<tên_riêng>` và gọi `saveState()`; tương thích dữ liệu cũ (luôn `|| {}`).
4. Nội dung tiếng Việt có dấu, giọng gần gũi, chuyên môn đúng (bạn là chuyên gia trong lĩnh vực được giao).
5. **Kiểm thử**: chạy `node -e "new Function(require('fs').readFileSync('<file>','utf8'))"` để kiểm tra cú pháp; mô phỏng logic thuần bằng Node. Harness giao diện ở `/tmp/harness/` (build.py ghép script của index.html thành 1 file HTML). Để thử module mới: copy `build.py` sang thư mục riêng `/tmp/<module>/`, sửa để chèn `<script>` của bạn (và `<style>` CSS) ngay trước `</body>` trước khi ghi file, ghép `common.js` + file test của bạn (xem mẫu `/tmp/harness/v_sess2.js`, `v_nu3.js`), xuất ra `/sessions/quirky-magical-gauss/mnt/outputs/_test/<module>-*.html`. Nếu bạn có công cụ present_files + screenshot_file_preview thì mở và chụp màn hình (chụp 2–3 lần vì timer chậm; khung xem trước không tải được mạng).
6. Viết `docs/INTEGRATION-<module>.md`: thẻ `<script>`/`<link>` cần thêm (thứ tự), thay đổi cần làm ở file khác (nếu có, ghi dạng diff), thay đổi firestore.rules (nếu có), cách thử, giới hạn.
7. Báo cáo cuối (≤ 300 từ, tiếng Việt): file đã tạo, tính năng, cách kiểm thử đã chạy, việc còn lại.
